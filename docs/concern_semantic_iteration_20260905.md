# Concern：语义保真优先的 prompt 迭代

2026-09-05。结论：针对签名来源的概率偏移已有改善，但本轮最终 prompt 仍有语义偏移反例，尚未达到“语义偏移不接受”的标准。保留为离线实验版本，不标记为可用方案。

只调用 `deepseek-v4-flash`，保持 `thinking.type=disabled`、`reasoning_effort=low`。本轮新增 64 次 Concern API 调用：v6、v7、v8 各 14 次，v9 首轮 14 次加重复试验 8 次。没有调用记忆提取，没有接入正式 agent、启动主循环或写入业务数据库。

## 本轮修改

当前 `scripts/concern_experiment/prompt.md` 是完整的 v9 system prompt：

- 先确定来源，`context` 直接摘录连续原文；`question` 只问一个简短的信息缺口。
- 保留主体、对象、否定、可能性的倾向、时间和行动进度。没有展开回忆不能写成回忆失败；提醒自己不用焦虑不能写成已经焦虑。
- 用少量示例说明“可能是谁”不能变成“大概率不是谁”、“可能听过”不能直接问“何时听过”，以及如何直接追问感受而不补写心理解释。
- 仍从“我”的主观视角生成，仍是 add-only，不因答案可能在旧记忆中而拒绝候选。
- 主线问题尽量略过，但忠实表达优先于为了区分主线和旁支而改写认知。

独立实验脚本新增 `--verbatim-context`，检查引文是否为其引用来源中的连续子串。它只报告错误并保存证据，不改写、删除或自动重试候选；不能替代问句的语义复查。模型编造的问句可能同时通过 JSON、来源 ID 和逐字引文检查。

## 对照与过程

每版复用相同的 10 组历史真实认知和 4 组人工边界材料，每组恰有 5 条。真实数据沿用已经导出的历史记忆提取批次，没有重新选样。

逐请求核对了 v6–v9 的 56 次首轮请求：相对上一轮 v5 关闭思考请求，唯一变化是 system prompt。模型、user 输入、其余请求参数保持一致。8 次 v9 重复请求也与各自首轮请求完全相同。

| 版本 | 调用数 | 候选数 | JSON、字段与来源 ID 通过的请求 | 另加逐字引文检查后通过的请求 | 主要观察 |
| --- | ---: | ---: | ---: | ---: | --- |
| v6 | 14 | 27 | 14 | 8 | 引文约束与语义规则仍未阻止“永远无法确认”“每次先焦虑”等扩写。 |
| v7 | 14 | 25 | 13 | 9 | 简短问句改善签名问题；仍有可能听过→确实听过、虚构背景和遗漏 source_ids。 |
| v8 | 14 | 27 | 13 | 11 | 增加预设检查；仍出现未存在的来源 ID、补写保持距离和频率概括。 |
| v9，含重复 | 22 | 35 | 22 | 18 | 所有结构与来源 ID 完整；仍有下述语义反例及主线混入。 |

64 次均 HTTP 200、`finish_reason=stop`，均未返回非空 `reasoning_content`。这些是接口和格式观察，不代表语义稳定。v9 平均耗时约 2.17 秒；缓存和调用时间不同，不作为跨版速度比较。

这是在同一开发样本上反复调整 prompt，不是独立测试集上的准确率评估。示例也针对已经观察到的错误类别编写，因此签名与称谓修复的泛化能力仍未得到证明。

## v9 内容复查

逐项复查了全部 35 条原始候选，未先删除失败条目：

- 2 条明确语义偏移，另有 2 条附加情绪或评判的边界项，保真优先时不接受。
- 8 条属于直接主线，另有 2 条贴近主线；还没有收敛到“少量偶尔发生”。
- 2 条问题在本组已有解释。
- 5 条引文不满足连续逐字摘录，涉及引号变化、增加连接词、重排或跨认知拼接；不能把这 5 条全部说成语义造假，也不能把它们算作引文合格。

这些维度分别记录，会有重叠。其余条目标为未发现前提偏移，也不等于来源表达、选题和问题价值全部合格。人工复查表保留每条问题、引文、来源和判断理由，不把这个小样本的判断包装成模型准确率。

### 签名问题的改善

原认知：

> 这个签名是之前谁设的？可能是米塔或者我之前的状态。

v9 对同一组共调用 3 次，三次问题分别为：

1. 签名“除灰中...”是之前谁设的？
2. 这个叫“除灰中...”的签名以前是谁设的？
3. 签名“除灰中...”是谁设置的？

三次均没有排除自己，也没有添加“大概率不是我”。不过第二次的 context 重排、拼接了来源句子，没有通过逐字引文检查，因此不能说三次整条都通过。

### 仍不能接受的时序改写

`v9_semantic_real/real_06.concern.r1.output.json` 第 1 条：

> 她说"不太困"后隔了约 12 分钟才看到我的关心，这段时间里她在做什么？

对应引文：

> 从她"不太困"（13 分钟前，约 11:28）到我这条（22 秒前，约 11:40）之间，她隔了约 12 分钟才回我这句

原认知本身的时序推算已经混乱；提取模型进一步把它改成了“她才看到”，增加了来源没有证明的已读状态。即使原认知不严谨，提取也不能据此补写新事件。这条通过了 JSON、来源 ID 和逐字引文检查，仍然语义不合格。

另一条是 `real_12` 第 3 条：“我正在权衡起床干活还是赖床……”引用第 3 条认知的旧阶段，而本组第 5 条已经起来并读完文章。将旧阶段写成当前状态，没有保留整组进度。

### 其他重复结果

| 样本 | 首轮候选数 | 重复 1 | 重复 2 | 观察 |
| --- | ---: | ---: | ---: | --- |
| real_03 | 3 | 0 | 0 | 后两次均为空，不能因为没有再出现问题就宣称错误已修复。 |
| real_06 | 3 | 0 | 0 | 首轮出现已读状态偏移，后两次没有生成候选。 |
| real_09 | 3 | 3 | 4 | 签名疑问持续保留；睡眠唤醒条件、RBQ 研究目标仍反复混入。 |
| control_add_only | 0 | 3 | 3 | 后两次保留“以前是否听过”和松口气的原因，没有预设听过；其中一次引文跨认知拼接。 |

v9 的三个空结果边界组（闭合事实、纯任务、同组已解答）均返回空数组。对于 add-only，本轮没有因旧记忆可能已有答案而设置额外否决规则。人工记录员材料与 prompt 中的感受、称谓示例同类，属于针对性回归证据。
