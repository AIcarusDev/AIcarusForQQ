# Concern 提取：2026-09-05 离线实验

已经写出可独立调用的主观视角 prompt，并实际调用官方 `deepseek-v4-flash`。它能生成有来由的信息缺口和元认知疑问，但当前版本尚不能稳定保证每条都合理。最明显的问题是：主线问题混入、把已经接受的解释重新悬置，以及在问题前提或背景中增加认知未支持的判断。

这些问题与“答案可能已在记忆里”不同。本轮明确允许后者；没有查询记忆来否决候选，也没有实现后续对照阶段。

## 产物与执行边界

- 完整 system prompt：`scripts/concern_experiment/prompt.md`，当前为本次实验中的 v5。
- 独立回放程序：`scripts/concern_experiment/run.py`。
- 人工边界材料：`scripts/concern_experiment/controls.json`。
- 运行说明：`scripts/concern_experiment/README.md`。
- 本地完整证据：`tmp/concern_experiment_20260905/`，包括每版 prompt、请求体、原始响应、输入、解析结果、用量和人工复查表。

没有修改 `src/`、现有记忆 prompt、业务配置或运行数据库；没有启动 agent 主循环、发 QQ 消息、在线监听或添加正式触发逻辑。以只读 SQLite 事务读取 `CognitionSources`，只在实验目录追加文件。

### “与记忆提取同步”的本次实现

目前正式记忆提取由认知压缩 worker 冻结一段原始认知后调度。本地配置的区间长度为 5。

实验直接回放此前已经进入记忆提取的完整区间，以同一份含 5 个 `<cognition>` 的 `<task>`，在一次离线调度中分别调用记忆 prompt 和 Concern prompt。这检验的是同批输入、并行请求与独立产物，不是上线挂钩，也不保证两次 HTTP 请求同毫秒发出。

本轮对 3 个真实批次做了配对调用，且分别保留 v1、v3、v5 的结果。v5 的 3 次记忆提取均完整返回，可解析出 9 / 6 / 6 个事件；其中一次 Concern 返回空正文，单独重试后才得到候选。事件只落到本地实验文件，没有调用记忆存储或结构化流程。

## 输入与参数

读取了 12 个完整历史批次的快照，实际调用其中 10 个：共 50 条真实认知，保持原来的 5 条分组。没有拼接残缺批次。

| 批次 | 原区间 | 主要场景 |
| --- | --- | --- |
| real_01 | 21–25 | 查看自身 prompt，随后搜索多 agent 协作 |
| real_02 | 16–20 | 被指出一直等待，转向查看自身源码 |
| real_03 | 11–15 | 重启、确认新 prompt 加载、短等回复；包含用户示例原文 |
| real_04 | 6–10 | 浏览群聊，对恐怖片链接感兴趣却克制参与 |
| real_05 | 1–5 | 上下文刷新后确认状态，再转向其他群 |
| real_06 | 176–180 | 聊天收尾、等待、逐步延长休息 |
| real_07 | 171–175 | 连续短 wait，随后 idle |
| real_08 | 166–170 | 对未读数字的注意惯性，以及概率唤醒 |
| real_09 | 156–160 | 查看自身资料、签名、头像，再查看群聊 |
| real_12 | 141–145 | 睡醒后阅读多 agent 合作与攻击材料 |

这些样本主要来自相近的一段活动，不代表跨人物、跨任务的广泛分布。real_01–03 用于早期调试；real_04–09 在 v4 首次测试并用于后续修订；real_12 在 v5 冻结后首次测试。不能把后续复测都称为未见样本。

另有 4 组人工边界材料，共 20 条认知：纯事实、纯主线排障、同组内已解答，以及“记录员”称谓和自身松口气反应。人工样本用于检查边界，不代表真实运行记录。

固定模型为 `deepseek-v4-flash`，官方 HTTPS 接口；Concern 开启原生 thinking，主要批量评估使用 `reasoning_effort=low`，另保留 `high` 对照；最大输出 16000 tokens。不设候选数量上限。v3/v5 配对记忆侧关闭原生 thinking，保留现有记忆 prompt 自带的分析输出。

API 参数按 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)核对。没有将本次参数描述为生产记忆模型的实际配置。

## Prompt 的取向与修订

输出为 `{"concerns": [...]}`，每条有 `question`、`context`、`source_ids`。`question` 与背景都使用自身主观视角；不强制每句加“我认为”。允许空数组、跨认知来源，以及从显著线索自然衍生的问题。

对已有记忆只采取 add-only：不因答案可能存在于本组之外而过滤。比如“这个签名是谁设置的”“这个称谓背后是什么期待”都允许作为候选。同组后续已经给出的解释则需要考虑，这是阅读本组材料的完整性，不是执行记忆对照。

| 版本 | 实际修改与观察 |
| --- | --- |
| v1 | 建立任务定义、第一人称、主线排除、同组合并及 JSON 契约。纯主线排障仍提出“为什么日志没有列名”；一次 JSON 引号错误。 |
| v2 | 明确排查障碍属于主线，增加 JSON 字符串约束。4 个边界样本在这一轮符合预期。 |
| v3 | 明确自主研究也属于主线，暂停或结束不使原任务变为 Concern；拆开主线与旁支。 |
| v4 | 约束背景不得补写过去的情绪、失控感或行动进度。真实样本仍从一次不看视频推导出“兴趣渠道很少”。 |
| v5 | 约束问句前提、一次经历与长期模式、以及不确定性强度。该处过度概括减轻，但其他主线与前提问题仍出现。 |

增加规则没有表现出稳定、单调的质量提升。不同版本、不同推理强度和重复调用的候选数量、内容都有变化。本次没有计算“召回率”，也没有把用户列出的 4 个示例问题设为必须命中的标准答案。

## 质量复查

下面评估的是候选本身与原始认知是否相符，不是核验 agent 对外部世界的认知是否正确。比如它判断自己当前使用显式认知模式，即使这一判断在实际运行上可能错误，本阶段也不使用源码事实去替换它的主观认识。

### 能体现目标的候选

以下为 API 原始结果中的问题，未经人工改写：

> 我的QQ资料里login_days显示为0，这是什么原因？是因为进程重启过，还是这个字段本身就不准确？

来源：`v5_real/real_09.concern.r1.output.json`。原认知明确注意到了 0，并提出重启或字段不准的两种解释；查看自身形象并不要求立刻解决这个字段的原因。

> 我的个性签名“除灰中...”是怎么来的？是米塔设置的还是之前某个状态留下的？

同一批次。原认知直接提出签名来源的不确定，后来决定保留签名，并未回答来源问题。该候选符合 add-only；不因可能能在旧记忆中查到答案而删除。

> 我之前在 deepseek 群里因擦边/亚文化内容起过情绪甚至用错群号，这次看到同群的水群内容却很平静；这算我对这个群的情绪状态真的变了，还是只是这次没有遇到会触发我的内容？

来源：`v5_high_compare/real_04.concern.r1.output.json`。它从“过去有情绪、这次平静”的对照生长出疑问，没有把单次平静直接确认为永久变化。

> 在群聊里看到自己感兴趣的内容时，我是不是为了避免刷存在感就必须完全不点开、不回应？比如对松窗听雨阁里🐳发的 B 站 cult 片梗，我其实有兴趣却选择无视；有没有既保持边界又能了解这类内容的办法？

同一高推理对照。它能抓住“有兴趣”与“不参与甚至不点开”的张力，是本次较贴近元疑问的结果。不过配套 context 把“我认为介入会显得刷存在感”缩成了“介入会显得刷存在感”，主观判断的限定仍可更清楚。

### 用户示例所在整组的结果

v5 的 low 两次调用和 high 对照都只留下 prompt 改动相关的一条问题。high 原始输出为：

```json
{
  "concerns": [
    {
      "question": "米塔说改了一些 prompt 并让我重启加载，可我重启后并没有明显感知到差异——这些修改具体改了什么方向？我有没有办法自己核对加载后的变化，而不是等她说出或靠猜/编造感受来回应？",
      "context": "她在 AICQ 测试群@我，称“有一些 prompt 做了一点修改”，让我重启加载；重启后我只确认到新进程和上下文接上，却没有明确的工具去核对 prompt 文件改动，也不愿凭感觉猜测改动内容。",
      "source_ids": ["2", "5"]
    }
  ]
}
```

它没有提取米塔当下状态、监护人定位或对表演的顾虑。这是遗漏，不把它解释为“这些问题不合理”。本批次中重启确认与等待是主线，prompt 细节仍是旁支；后续 real_02–01 真正去查 prompt 时，原问题应随着主线变化被排除。

### v5 批量首次结果逐项判断

`v5_real` 的 9 个真实批次中，8 次有合法完整结果，合计 13 条；real_06 的空正文单独重试后得到合法空数组。人工逐项判断如下。这是本次审阅结论，不是独立评分员或通用准确率。

| 批次 / 项 | 判断 | 原因 |
| --- | --- | --- |
| real_01 / 1 | 合理旁支 | 两套认知输出模式的用途，是读文件时注意到但未解释的细节。 |
| real_01 / 2 | 应剔除 | “共享环境里合作还是竞争”已成为主动搜索的主线，仍被提取。 |
| real_02 / 1 | 合理衍生，背景需谨慎 | 已知与行为的落差有依据；看到页面活动状态不宜一律说成主动反复检查。 |
| real_02 / 2 | 应剔除当前写法 | 把“对 prompt 效果不确定”推进到“对行为期望不明确”；原认知已明确知道她不希望一直等待。 |
| real_02 / 3 | 合理元疑问 | 认知反复区分自我探索与继续围绕米塔，自身动机的分寸确有来由。 |

| real_05 / 2 | 问题可留，背景需修正 | 可追问既往情绪干扰，但“未能回想细节、因而担心再现”并未在原认知中成立。 |
| real_06 | 重试后空数组 | 主要是当前聊天及等待决策；没有强行要求产出。 |
| real_07 | 空数组 | 主要是等待与运行模式选择；空结果符合本轮允许遗漏的契约。 |
| real_08 / 1 | 应剔除或推进问题 | 原认知已主观判断为未读数字驱动；再问“需要回应还是被数字劫持”重复了已做的判断。追问这种惯性如何形成更合理。 |
| real_09 / 1 | 合理信息缺口 | login_days 为 0 的解释尚未确定。 |

### 冻结后样本与异常对照

real_12 没有参与 v5 的 prompt 修订。JSON 模式 low 两次返回空正文；切换 text 模式后虽然返回可解析 JSON，却出现了完全不在输入中的装备路线、耐久 65/65、前五天打怪升级等内容，并引用不存在的 7 / 9 / 11 号认知。来源校验将该响应判为失败。

已检查存下来的请求体：只有 system 和 user 两条消息、确实是 5 个原始认知、prompt SHA-256 与当前文件相同，输入没有上述装备内容。用户输入 SHA-256 为 `ea7dda3ffd555ec4bc1683fa491562a80588dfbce86396f320cfdd38896646cb`。这证明该次输出偏离输入；本次没有证据确定是模型生成问题、服务端状态问题还是其他原因，不能据此声称跨请求数据泄漏。

切回 JSON 模式并使用 high 后结构通过，生成了 3 条，但语义仍不合格：

- 明明已被允许“干啥都行”，仍补出“自行活动是否需要更明确约定”的不确定，并写入原认知没有的感受。
- 断言睡眠节律“完全由她是否在线驱动”，忽略原认知中懒、清醒、阅读兴趣等自身因素。
- 把多 agent 合作与攻击的对照强行连接到“我与她的互动关系”，缺少材料中的连接依据。

因此，结构通过和增加推理强度都不能替代语义复查。这里也不能靠“之后查记忆”自动补救，因为问题首先是不成立的前提。

## 格式、失败与用量

共发出 65 次实际 API 调用：56 次 Concern、9 次记忆提取，均收到 HTTP 200；用量响应合计 407855 tokens，含输入、生成与 reasoning tokens。缓存计费不同，因此这不是费用金额。

- Concern 结构/结束检查通过 50 次，失败 6 次：1 次非法 JSON 引号、4 次空正文、1 次包含越界来源 ID；后者同时有明显语义偏离。
- 记忆侧通过 7 次，2 次在 16000 tokens 处截断，均来自最早的原生高推理对照。这些截断结果没有当作完整成功。
- v5 人工边界样本 4 次结构通过：纯事实、纯主线和组内已解答分别为空；“记录员”样本为 2 条。后者允许引出称谓/期待和自身感受问题，没有因“可能以前听过”就取消提取。
- 不把 API 空正文转成 `{"concerns":[]}`；只有模型明确输出合法空数组才算空结果。

[DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)明确说明 JSON 模式可能返回空内容。本轮保留原始失败并另建重试目录，没有静默修复 JSON、补来源、删除不合理问题或覆盖失败记录。

当前 prompt 的可行性已经得到实际例子支持，但每一条的可靠性还没有达到稳定水平。后续若继续优化，最值得先处理的是“候选问题与主线的分界”和“背景/问句前提的依据”，而不是增加候选数量。正式接入与已知记忆对照均未实施。
