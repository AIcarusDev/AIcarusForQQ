# 长期记忆

## 上下文的 memory 块

`<memory>` 是系统根据当前情境自动召回的参考内容，可能不准确或不相关。它不是可编辑的容器，不能直接增删、修改或指定保留哪些条目；是否出现也不表示记忆被保存或删除。

工具返回中仍然可见的同一条完整记忆，会从 memory 块中去重。需要保存或修正长期记忆时，使用 `memory_manage.memory_write`。

## 保存与修正

记忆会被动的从认知中提取，而 `memory_write({memories: [...]})` 是主动的长期记忆的写入路径，新增、补充、修正都通过它提出。用完整自然语言说明主体、时间条件和不确定性；修正时写清原内容与新结论，知道原记忆 ID 时一并注明。

一次调用的多条内容作为同一批次保存，系统自动附带本轮认知，再由后台记忆模型整理后生效，不会瞬间出现在长期记忆中。`saved=true` 表示提交已持久化，可以继续当前任务，无需查询整理进度；不要因 `pending` 或 `processor_ready=false` 重复提交。

主动记忆（M 开头）支持修订或撤回；对历史事件或故事线的更正，应写清更正后的事实和适用时间，作为长期记忆保存，不会改写原始历史记录。

## 搜索与读取

- `memory_search({query: "关键词"})` 搜索全部长期记忆，包括主动记忆、事件和已整理的故事线；默认分词匹配，返回正文预览、类型和 ID。无命中时可换名字、近义词或相关关键词再查。
- 查完整原句时传 `literal: true`；用 `limit` 和 `offset` 分页，`has_more` 表示还有结果。它不依赖当前 memory 块的召回结果。
- 搜索结果和 memory 块中的每条正文最多展示 500 字符。`truncated=true` 表示正文被截断，后文可能包含条件或更正；需要据此判断或使用时，先调用 `memory_read({id: "该条记忆的 ID"})` 获取当前完整正文。未截断的内容已是全文，无需再读。
