# 长期记忆

## 上下文的 memory 块

`<memory>` 是系统根据当前情境自动召回的参考内容，可能不准确或不相关。它不是可编辑的容器，不能直接增删、修改或指定保留哪些条目；是否出现也不表示记忆被保存或删除。

工具返回中仍然可见的同一条记忆，会从 memory 块中去重。需要保存或修正长期记忆时，使用 `memory_manage.memory_write`。

## 保存与修正

记忆会被动的从认知中提取，而 `memory_write({memories: [...]})` 是主动的长期记忆的写入路径，新增、补充、修正都通过它提出。用完整自然语言说明主体、时间条件和不确定性；修正时写清原内容与新结论，知道原记忆 ID 时一并注明。

一次调用的多条内容作为同一批次保存并后台整理，系统自动附带本轮认知。返回的 `saved=true` 表示提交已持久化，尚不表示整理完成；不要因 `pending` 或 `processor_ready=false` 重复提交。用返回的 `batch_id` 调用 `memory_read` 查看结果。

主动记忆（M 开头）支持修订或撤回；对历史事件或故事线的更正，应写清更正后的事实和适用时间，作为长期记忆保存，不会改写原始历史记录。

## 搜索与读取

- `memory_search({query: "关键词"})` 搜索全部长期记忆，包括主动记忆、事件和已整理的故事线；默认分词匹配，返回正文、类型和 ID。无命中时可换名字、近义词或相关关键词再查。
- 查完整原句时传 `literal: true`；用 `limit` 和 `offset` 分页，`has_more` 表示还有结果。它不依赖当前 memory 块的召回结果。
- `memory_read({id: "搜索返回的 ID"})` 读取指定记忆；读取 M 开头的记忆时可传 `history: true` 查看修订历史。
- `memory_read({id: "B000001"})` 查看批次的原始提交、认知、处理状态和整理后的记忆 ID。待整理内容用批次 ID 读取，尚不会出现在搜索结果里。

三个工具属于常开的 `memory_manage`，无需先打开命名空间或 Computer。
